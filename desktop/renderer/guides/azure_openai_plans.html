1Do this in LUCID right now

The short version

There is no OAuth button on this card and no plan to buy. Create an Azure OpenAI resource in your tenant, deploy the models you want, then fill two fields in LUCID: the resource key and the resource name. Everything else has a working default.

In Settings > Providers > Azure OpenAI, the card takes four fields:

FieldRequired?What to put there
AZURE_OPENAI_API_KEYYes A key from your Azure OpenAI resource (Azure portal: your resource, then Keys and Endpoint).
Resource name or base URLYes Either the bare resource name, or the full base URL if your setup uses a custom endpoint. One or the other, not both.
API versionNo Defaults to v1. Leave it alone unless your resource pins an older version.
Deployment mapNo Only needed when your Azure deployment names differ from the model ids LUCID shows. Map model-id = your-deployment-name, one per line. If you named deployments after the models, skip it.
API key auth API version defaults to v1 Deployment map optional No OAuth on this card

Model not found? Check the deployment, not the key

Azure only serves models you have explicitly deployed on the resource, under the name you gave the deployment. A valid key with a missing or differently named deployment is the most common failure: fix it in the Azure portal or add a deployment map line, not by rotating keys.

2What Azure OpenAI actually is

The same OpenAI models, hosted inside your Microsoft Azure tenant and billed per token on your Azure invoice. There are no consumer plans, no seats, and no chat subscription: it is infrastructure, priced like the rest of your cloud.

What the tenant boundary buys you:

  • Data residency: you choose the region your prompts and completions are processed in.
  • Network control: VNet integration and private endpoints keep traffic off the public internet.
  • IAM: Azure role-based access control governs who can call which resource.
  • Compliance: the certifications and contractual terms your Azure agreement already carries.
  • Spend consolidation: usage counts toward existing Azure commitments and shows up on the invoice your finance team already reads.

The setup flow on the Azure side: create an Azure OpenAI resource, then deploy each model you want under a deployment name, then use the resource key and endpoint. LUCID takes it from there with the four fields above.

3When to pick it over an OpenAI key

SituationPickWhy
Org already on AzureAzure OpenAI One invoice, existing commitments, IAM you already administer. The models are identical.
Compliance-driven teamAzure OpenAI Residency, retention, and network isolation are contract terms here, not enterprise-tier negotiations with OpenAI.
Defense or regulated adjacencyAzure OpenAI or AskSage Your tenant's governance applies to every token. For org-issued gov gateways, the AskSage card in LUCID is the dedicated path.
Solo dev, personal projectsOpenAI key Azure adds resource setup, deployments, and portal hops without saving money: it is not the cheapest path for a solo dev. Paste OPENAI_API_KEY on the OpenAI card instead.
Want subscription economicsChatGPT plan Azure is per-token only. Flat monthly pricing lives on the OpenAI card's OAuth path; see the OpenAI plans guide.

Rule of thumb

If nobody in your org says the words tenant, VNet, or residency, start with a plain OpenAI key. The day procurement or compliance says them, move the same workloads here: the models do not change, only the wrapper does.
