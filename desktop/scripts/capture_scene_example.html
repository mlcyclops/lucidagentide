CREATOR-3b reference scene

One canvas, one function, the same pixels every run

The LUCID capture bridge hands this page a plan of times. For each one it calls window.lucidRenderAt(tMs) and reads the canvas straight back. Nothing below consults a clock, rolls a die, carries state between calls, or fetches a byte, so asking for the same millisecond twice paints byte-identical pixels. That is the whole contract, and this file is both the demonstration of it and the thing to copy when you write your own scene.

The contract

window.lucidRenderAt = function (tMs) { /* paint the scene at tMs, return nothing */ };
  • Identical tMs must paint identical pixels. Not similar, not close: the audit compares fingerprints of the raw readback, so one antialiased edge is a difference.
  • The time is an argument, never a reading. Your scene is told which instant to paint. It is not asked what time it is.
  • Define it before a capture can run. This script sits at the end of the body, and the bridge is injected after it, so the function exists by the time any message arrives.
  • Return nothing and finish synchronously. The readback happens in the same task as the call, so a promise resolved later has already missed the frame.

What the bridge does

  • It captures the largest canvas on the page unless it is handed a CSS selector. This page has exactly one canvas, so there is nothing to disambiguate.
  • It reads pixels with toDataURL("image/png") in the same synchronous task as the render call. The live loop below can never slip a frame in between the two.
  • Caps per pass: 64 frames and no canvas edge over 2048px. This canvas is 480 by 270, and a 2000 ms pass at 30fps is 60 frames, which fits one whole loop with room to spare.
  • A page with no lucidRenderAt can only be sampled on its own clock, and the result says so rather than pretending to be a driven capture.
  • The audit flags a run of three or more identical consecutive frames as stuck, which is the signature of a scene that ignored the time it was handed.

The four things that break determinism

breaker 1

The wall clock

Date.now(), performance.now(), new Date(), and the timestamp requestAnimationFrame hands your callback. Each one makes a frame depend on when it was painted instead of which moment it was asked for. The live loop here declares its callback with no parameter at all, so the rAF timestamp is not even in scope.

breaker 2

Randomness

Math.random(), crypto.getRandomValues(), any unseeded noise field. If your scene wants noise, derive it from tMs and a fixed seed with a small integer hash so frame 47 is the same speckle pattern on every run. In this file the only call to Math.random lives inside the deliberately broken variant.

breaker 3

Unseeded accumulation

Physics or particles advanced with state += step on every call. Frame N then depends on how many times you were called and in what order, so a pass that renders 500 ms first disagrees with a pass that reaches it fifteenth. Solve for tMs instead of stepping toward it. The comet tails below are drawn by re-evaluating the same pure position function at tMs - k * step, never by remembering where a body used to be.

breaker 4

External assets

Images, webfonts, CDN scripts, fetch. The preview frame sets connect-src 'none', so they never arrive. Even where they do, a half-loaded asset paints one way on the first pass and another way on the second. Every pixel here is drawn by code, and the canvas is never tainted, which is also why the readback cannot be refused.

The broken variant, present and disabled

A second renderer ships alongside the honest one so you can watch the harness earn its keep. It adds a sub-pixel Math.random() wobble to the moving layer. That is enough: every antialiased edge shifts, so every fingerprint changes, while to the eye the scene still looks completely right. An invisible failure that a compare catches is exactly the class of bug this harness exists for.

// Paste in the console, or uncomment the swap at the bottom of the script, then re-run a capture.
window.lucidRenderAt = window.lucidRenderAtNondeterministic;

Captured frames painted through it carry a red NONDETERMINISTIC badge, so a reviewer reading a contact sheet can tell at a glance which renderer produced it. The default export stays the honest one.

Determinism here is per machine and per browser build: the same binary asked for the same millisecond always paints the same bytes. Text metrics and antialiasing can differ across GPUs and font stacks, so compare a capture against another run of the same plan on the same machine, not against a screenshot taken somewhere else.
