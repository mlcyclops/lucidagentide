Coming in 2.3.0

A Windows sandbox chat works inside

The agent runtime runs inside a Windows AppContainer: files only in the folders it has been granted, no direct internet, and model traffic through LUCID's audited proxy. The pill turns green only after the real runtime boots inside it. The Security panel has the switch, a Windows folder picker, and the list of every folder the sandbox can reach.

Coming in 2.3.0

Jev, typed judgment

Classifications, yes/no checks and scores come back as typed answers with probabilities and a confidence, not a keyword parsed out of prose. Add a TypeSafe key under Settings, and every judgment in a turn is drawn under the reply. No key, and the same calls fall back to your chat model.

Coming in 2.3.0

A browser agent that reads before it clicks

Give it one goal. It reads the page's real controls and has Jev pick each click, dropdown and field from what is actually on screen. No model ever writes the text it types: every typed value is one you supplied.

Coming in 2.3.0

The newest models

Claude Opus 5.5 is the new default, and GPT-6 Astra, Sol and Luna are in the picker with cost cards and their real 1M context windows. Grok 4.7 joins them under a new xAI Grok family.

Coming in 2.3.0

Several accounts per provider

Keep multiple sign-ins or named API keys on one provider and switch between them in Settings or the Provider Hub. Inactive accounts are parked, never deleted.

Coming in 2.3.0

Fewer dead ends

Past sessions open again, a leftover engine from an earlier session no longer blocks launch (LUCID names it and offers to stop it), an external link in a preview no longer blanks the window, and agent errors read as words instead of [object Object].

Found a bug?

Open an issue on GitHub with what happened, a screenshot, and your logs. Three minutes of your time saves us days of guessing.

Step 1

Check, then open an issue

Look through the open bugs first. New one? Open an issue: the form asks for your LUCID version from the About button at the bottom of the left rail, your OS, the model you used, the steps, and what you expected.

Step 2

Show us

Capture the whole window (Win+Shift+S, Cmd+Shift+4 then Space, or PrtSc) and paste it into the issue. For a sandbox problem include the Security panel; for a blocked tool call, turn on Developer mode and include the Logs panel.

Step 3

Attach your logs

On Windows, one command builds a redacted support zip. On macOS and Linux, attach three log files. Both are below.

Windows: build a support zip with one command

Open PowerShell (Start, type PowerShell) and run:

powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Programs\LucidAgentIDE\resources\repo\tools\collect-support-logs.ps1"

It writes lucid-support-<date>-<time>.zip to your Desktop: the engine log, the last 7 days of agent runtime logs, a redacted settings summary, and a system report. Keys, tokens and passwords are redacted and the credential vaults are never read. It does include your sign-in email, folder paths and the last four characters of each key, so open the zip and remove anything you would not post publicly.

Script not at that path? Download it and run it:

irm https://raw.githubusercontent.com/mlcyclops/lucidagentide/master/tools/collect-support-logs.ps1 -OutFile "$env:TEMP\collect-support-logs.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\collect-support-logs.ps1"
macOS and Linux: attach three log files

The engine log (~/Library/Application Support/lucidagentide-desktop/engine.log on macOS, ~/.config/lucidagentide-desktop/engine.log on Linux), the runtime stderr (~/.omp/lucid-acp.log), and the newest one or two runtime daily logs (~/.omp/logs/omp.*.log). One command zips them:

# macOS
cd ~ && zip -j ~/Desktop/lucid-logs.zip "Library/Application Support/lucidagentide-desktop/engine.log" .omp/lucid-acp.log $(ls -t .omp/logs/omp.*.log | head -2)
# Linux
cd ~ && tar czf ~/lucid-logs.tar.gz .config/lucidagentide-desktop/engine.log .omp/lucid-acp.log $(ls -t .omp/logs/omp.*.log | head -2)

These files are not redacted: search them for sk-, Bearer, token and key before you attach them.

Never attach these files
~/.omp/lucid-gui.json holds provider keys in plain text. ~/.omp/agent/agent.db and ~/.omp/lucid-cred-vault/ are your credential vaults. Anything under ~/.omp/logs/http-400-requests/ is a full copy of a rejected request, including your prompt and file contents.

Issues are public. Never paste an API key, token, password, or CUI into an issue, a screenshot, or a log.
